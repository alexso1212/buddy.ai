## 1. RESPONSE RENDERING PIPELINE

When the user sends a message, the following stages execute **sequentially**:

```
User taps Send
    │
    ▼
[Phase 0] User message animates into chat flow (0ms)
    │  - Message bubble slides up from input area
    │  - Input field clears and collapses to default height
    │  - Chat auto-scrolls to bottom
    │
    ▼
[Phase 1] Thinking indicator appears (0-2000ms wait)
    │  - Orange starburst icon with rotation animation
    │  - No text, just the animated icon
    │  - This is the "waiting for first token" state
    │
    ▼
[Phase 2] Extended Thinking bar (if model uses thinking)
    │  - Replaces the thinking indicator
    │  - Shows collapsible bar with timer icon + summary text
    │  - Summary text updates in real-time during thinking
    │  - Bar has "breathing" shimmer animation while active
    │  - When thinking completes: bar becomes static, chevron appears
    │
    ▼
[Phase 3] Streaming text body
    │  - Main response text streams token-by-token
    │  - Classic typewriter effect, left-to-right, top-to-bottom
    │  - Page auto-scrolls to follow new content
    │
    ├──► [Phase 4a] Inline tool call card (if model calls a tool)
    │    - Appears at the exact position in the token stream
    │    - Shows tool name + loading spinner
    │    - Collapses to result summary when complete
    │    - Text streaming PAUSES during tool execution
    │    - Text streaming RESUMES after tool returns
    │
    ├──► [Phase 4b] Inline artifact card (if model creates artifact)
    │    - Appears at the exact position in the token stream
    │    - Shows file icon + artifact title
    │    - If large: shows "responding in background" banner
    │    - Artifact renders in side panel (desktop) or bottom sheet (mobile)
    │    - Text streaming continues (non-blocking)
    │
    ├──► [Phase 4c] Inline code block (if model writes code)
    │    - Code container border renders first
    │    - Code text streams inside the container
    │    - Syntax highlighting applies in real-time
    │    - "Copy" button fades in when block completes
    │
    ├──► [Phase 4d] Interactive widget (if model sends choices)
    │    - Appears at end of response
    │    - Slides up from below with spring animation
    │    - Shows single-select / multi-select / rank options
    │
    ▼
[Phase 5] Response complete
    │  - Streaming stops
    │  - Action buttons fade in below response (copy, retry, thumbs up/down)
    │  - Stop button in input area reverts to Send button
    │  - Any pending artifacts finish rendering
    │
    ▼
[IDLE] Waiting for next user input
```

## 2. COMPONENT ARCHITECTURE

```
<ChatContainer>
  <MessageList>                          // Virtual scroll container
    <UserMessage />                      // User's message bubble
    <AssistantResponse>                  // One response = one container
      <ThinkingIndicator />             // Phase 1: spinning starburst
      <ExtendedThinkingBar />           // Phase 2: collapsible thinking summary
      <StreamingTextBlock>              // Phase 3: main text
        <TextToken />                   // Individual streaming tokens
        <ToolCallCard />                // Phase 4a: inline tool call
        <ArtifactCard />                // Phase 4b: inline artifact
        <CodeBlock />                   // Phase 4c: inline code
        <CitationTag />                 // Phase 4d: inline citation superscript
      </StreamingTextBlock>
      <InteractiveWidget />             // End-of-response choices
      <ActionButtons />                 // Post-response actions
    </AssistantResponse>
  </MessageList>
  <InputArea>
    <StopButton />                      // During streaming
    <SendButton />                      // When idle
  </InputArea>
</ChatContainer>
```

## 3. COLOR SYSTEM

### Spacing Philosophy (Critical)

> **Process elements are compact, not blocky.**
> Thinking bars, tool cards, artifact cards, and background banners are “inline” elements embedded in the text flow. They should feel like part of the text stream, NOT like separate card sections with large gaps. Use tight vertical margins (4-6px) between process elements and surrounding text. Only the main content paragraphs and code blocks get slightly larger spacing (8-12px). The overall feel should be a continuous, dense conversation — not a dashboard of spaced-out cards.

All colors are for **dark theme** (Claude’s default dark mode).

```css
:root {
  /* ── Background layers ── */
  --bg-primary:         #1a1a1a;    /* Main chat background */
  --bg-secondary:       #2a2a2a;    /* Cards, code blocks, collapse bars */
  --bg-tertiary:        #333333;    /* Hover states on cards */
  --bg-user-message:    #3b3b3b;    /* User message bubble */
  --bg-input:           #2a2a2a;    /* Input field background */
  --bg-overlay:         rgba(0, 0, 0, 0.5);  /* Modal/sheet backdrop */

  /* ── Text colors ── */
  --text-primary:       #e8e8e8;    /* Main response text — warm off-white */
  --text-secondary:     #a0a0a0;    /* Metadata, timestamps, tool labels */
  --text-tertiary:      #6b6b6b;    /* Placeholder text, disabled states */
  --text-user:          #ffffff;    /* User message text — pure white */
  --text-code:          #e8e8e8;    /* Code text inside code blocks */

  /* ── Brand / Accent ── */
  --accent-orange:      #d4714a;    /* Claude starburst icon, loading states */
  --accent-orange-dim:  #a0553a;    /* Starburst icon dimmed rays */
  --accent-blue:        #7ab5e0;    /* Links, interactive elements */
  --accent-blue-hover:  #9ccaf0;    /* Link hover state */
  --accent-green:       #6bc76b;    /* Success states, completed tool calls */

  /* ── Borders ── */
  --border-subtle:      #3a3a3a;    /* Card borders, dividers */
  --border-code:        #404040;    /* Code block borders */

  /* ── Special ── */
  --thinking-shimmer:   linear-gradient(90deg, transparent 0%, rgba(255,255,255,0.04) 50%, transparent 100%);
  --glass-bg:           rgba(42, 42, 42, 0.85);
  --glass-blur:         12px;       /* backdrop-filter: blur(12px) */
}
```

**Light theme overrides** (for future):

```css

  --bg-primary:         #ffffff;
  --bg-secondary:       #f5f5f5;
  --bg-user-message:    #e9e9e9;
  --text-primary:       #1a1a1a;
  --text-secondary:     #6b6b6b;
  --border-subtle:      #e0e0e0;
}
```

## 4. TYPOGRAPHY SYSTEM

```css
:root {
  /* Font family — matches Claude's system font stack */
  --font-body:    -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif;
  --font-code:    "SF Mono", "Fira Code", "Cascadia Code", "JetBrains Mono", Menlo, Consolas, monospace;

  /* Font sizes */
  --text-xs:      12px;    /* Timestamps, citation numbers */
  --text-sm:      13px;    /* Tool labels, metadata */
  --text-base:    15px;    /* Main body text (mobile: 16px to prevent iOS zoom) */
  --text-lg:      16px;    /* Extended thinking summary */
  --text-xl:      18px;    /* Section headers in response */
  --text-code:    13px;    /* Code block content */

  /* Line heights */
  --leading-tight:   1.3;
  --leading-normal:  1.6;   /* Body text — generous for readability */
  --leading-code:    1.5;

  /* Font weights */
  --weight-normal:  400;
  --weight-medium:  500;
  --weight-bold:    600;    /* Bold text in responses, headers */
}
```

**Text rendering rules**:

- Body text: `--text-base`, `--leading-normal`, `--weight-normal`, color `--text-primary`
- Bold text: same size, `--weight-bold`, same color
- Italic text: same size, font-style italic, same color
- Inline code: `--font-code`, `--text-code` size, background `--bg-secondary`, border-radius 4px, padding 2px 6px
- Headers in response (## / ###): `--text-xl`, `--weight-bold`, margin-top 24px, margin-bottom 8px

```svg
    <line x1="0" y1="3"   x2="0"    y2="10"   stroke="#d4714a" stroke-width="2.2" stroke-linecap="round" opacity="1.0"/>
    <line x1="-2.6" y1="1.5" x2="-8.7" y2="5"  stroke="#d4714a" stroke-width="2.0" stroke-linecap="round" opacity="0.85"/>

    <line x1="-2.6" y1="-1.5" x2="-8.7" y2="-5" stroke="#d4714a" stroke-width="2.0" stroke-linecap="round" opacity="0.85"/>
  </g>

```

**Animation**: Slow continuous rotation, 3 seconds per full turn, ease-in-out. Additionally, each ray has a sequential opacity pulse (0.4 → 1.0 → 0.4) creating a “sparkle” effect.

```css
@keyframes starburst-rotate {
  from { transform: rotate(0deg); }
  to   { transform: rotate(360deg); }
}

@keyframes starburst-pulse {
  0%, 100% { opacity: 0.4; }
  50%      { opacity: 1.0; }
}

.starburst-icon {
  animation: starburst-rotate 3s linear infinite;
}

.starburst-icon line:nth-child(1)  { animation: starburst-pulse 1.5s ease-in-out 0.0s infinite; }
.starburst-icon line:nth-child(2)  { animation: starburst-pulse 1.5s ease-in-out 0.15s infinite; }
.starburst-icon line:nth-child(3)  { animation: starburst-pulse 1.5s ease-in-out 0.3s infinite; }
/* ... stagger each ray by 0.15s */
```

## 6. ANIMATION SPECIFICATIONS

### 6.1 Global Easing Functions

```css
:root {
  --ease-out-quart:    cubic-bezier(0.25, 1, 0.5, 1);      /* Primary exit easing */
  --ease-out-back:     cubic-bezier(0.34, 1.56, 0.64, 1);   /* Springy overshoot */
  --ease-in-out-sine:  cubic-bezier(0.37, 0, 0.63, 1);      /* Smooth breathing */
  --ease-spring:       cubic-bezier(0.22, 1.0, 0.36, 1.0);  /* Slide-in spring */
}
```

### 6.2 Fade-In (Used everywhere)

```css
@keyframes fadeIn {
  from { opacity: 0; }
  to   { opacity: 1; }
}

.fade-in {
  animation: fadeIn 300ms var(--ease-out-quart) forwards;
}
```

### 6.3 Slide-Up + Fade (User message, widgets)

```css
@keyframes slideUpFade {
  from {
    opacity: 0;
    transform: translateY(12px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

.slide-up {
  animation: slideUpFade 350ms var(--ease-spring) forwards;
}
```

### 6.4 Thinking Shimmer (Extended Thinking bar while active)

```css

.thinking-shimmer {
```

## 19. SCROLL BEHAVIOR

This is critical for a good streaming experience.

### Rules:

1. **Auto-scroll ON by default**: When new tokens arrive, the chat container scrolls to keep the latest content visible.
1. **User scroll interrupts auto-scroll**: If the user scrolls up manually (even a small amount), auto-scroll STOPS. The user is now in “browsing mode.”
1. **Re-engage auto-scroll**: Auto-scroll resumes ONLY when the user scrolls back to the bottom (within ~50px of the bottom edge).
1. **Smooth scroll**: Use `scrollTo({ behavior: 'smooth' })` for auto-scroll, but throttle to ~60fps to avoid jank.
1. **New message jump**: When user sends a new message, always force-scroll to bottom regardless of current position.

### Implementation:

```typescript
const chatContainerRef = useRef<HTMLDivElement>(null);
const isAutoScrolling = useRef(true);

// Check if user is near bottom
function isNearBottom(): boolean {
  const el = chatContainerRef.current;
  if (!el) return true;
  return el.scrollHeight - el.scrollTop - el.clientHeight < 50;
}

// On user scroll
function handleScroll() {
  isAutoScrolling.current = isNearBottom();
}

// Called on each new token
function scrollToBottom() {
  if (!isAutoScrolling.current) return;
  const el = chatContainerRef.current;
  if (el) {
    el.scrollTo({
      top: el.scrollHeight,
      behavior: 'smooth'
    });
  }
}

// On user sends message — always scroll
function onUserSend() {
  isAutoScrolling.current = true;
  scrollToBottom();
}
```

### State Machine

```typescript
type StreamPhase =
  | 'idle'            // No active stream
  | 'waiting'         // Phase 1: Sent request, waiting for first event
  | 'thinking'        // Phase 2: Extended thinking in progress
  | 'streaming'       // Phase 3: Text is flowing

  | 'complete';       // Phase 5: Stream finished

interface ResponseState {
  phase: StreamPhase;
  thinkingText: string;         // Accumulated thinking summary
  thinkingComplete: boolean;
  bodyTokens: ReactNode[];      // Ordered list of rendered elements
  activeToolCalls: Map<string, ToolCallState>;
  artifacts: Map<string, ArtifactState>;
  widget: WidgetConfig | null;
  isStreaming: boolean;
}
```

### Event Handler (Pseudocode)

```typescript
function handleStreamEvent(event: StreamEvent, state: ResponseState) {
  switch (event.type) {

    case 'thinking':
      // Phase 2: Update thinking bar text
      state.phase = 'thinking';
      state.thinkingText += event.content;
      // UI: Show/update ExtendedThinkingBar with shimmer
      break;

    case 'thinking_done':
      // Thinking complete, prepare for text
      state.thinkingComplete = true;
      // UI: Remove shimmer from thinking bar, show chevron
      break;

    case 'text':
      // Phase 3: Append text token to body
      state.phase = 'streaming';
      state.bodyTokens.push(<TextToken text={event.content} />);
      // UI: Token appears at cursor position, trigger auto-scroll
      break;

    case 'tool_use':
      // Phase 4a: Insert tool card at current position in body
      state.phase = 'tool_executing';
      state.activeToolCalls.set(event.tool_id, {
        name: event.tool_name,
        status: 'loading'
      });
      state.bodyTokens.push(<ToolCallCard id={event.tool_id} />);
      // UI: Tool card appears with slideUpFade + spinner
      // Text streaming PAUSES
      break;

    case 'tool_result':
      // Tool finished, update its card
      state.activeToolCalls.get(event.tool_id).status = 'complete';
      state.activeToolCalls.get(event.tool_id).result = event.content;
      state.phase = 'streaming';
      // UI: Spinner → green check, text streaming RESUMES
      break;

    case 'artifact_start':
      // Phase 4b: Insert artifact card at current position
      state.artifacts.set(event.artifact_id, {
        title: event.artifact_title,
        type: event.artifact_type,
        status: 'generating',
        content: ''
      });
      state.bodyTokens.push(<ArtifactCard id={event.artifact_id} />);
      // UI: Artifact card appears with slideUpFade
      // If large: show BackgroundProcessingBanner
      // Text streaming CONTINUES (non-blocking)
      break;

    case 'artifact_content':
      // Artifact content streaming (goes to side panel, not main chat)
      state.artifacts.get(event.artifact_id).content += event.content;
      // UI: Content renders in artifact panel
      break;

    case 'artifact_end':
      state.artifacts.get(event.artifact_id).status = 'complete';
      // UI: Remove background banner, artifact card becomes fully interactive
      break;

    case 'widget':
      // End-of-response interactive widget
      state.widget = event.widget_data;
      // UI: Widget slides up with staggered animation
      break;

    case 'done':
      // Phase 5: Stream complete
      state.phase = 'complete';
      state.isStreaming = false;
      // UI: Action buttons fade in after 200ms delay
      // UI: Stop button → Send button
      break;
  }
}
```

### KEY ORDERING RULE

> **The order of elements in `bodyTokens[]` array is SACRED.**
> Every token, tool card, artifact card, and code block is pushed in the exact order the model outputs them.
> The UI renders this array top-to-bottom.
> NEVER reorder, group, or defer elements to the end.

This means if the model outputs:

```
"Here's what I found: " → [tool_use: web_search] → [tool_result] → "The results show..."
```

The user sees:

```
Here's what I found:
┌─ 🔍 Searched the web... ──────────┐
└────────────────────────────────────┘
The results show...
```

NOT:

```
Here's what I found: The results show...
┌─ 🔍 Searched the web... ──────────┐   ← WRONG: pushed to end
└────────────────────────────────────┘
```
