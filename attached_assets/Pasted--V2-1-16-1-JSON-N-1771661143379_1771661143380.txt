# 德湃任务中心 V2 — 第1轮：核心骨架

## 项目概述

给16人金融教育公司做的团队任务看板。第1轮只做**登录 + 看板 + 状态管理 + JSON同步**。

## 技术栈

- **Next.js 14** (App Router)
- **PostgreSQL**（Replit 自带，连接字符串从环境变量 `DATABASE_URL` 读取）
- **Prisma** ORM
- **JWT (jose)** 认证，httpOnly cookie
- **Tailwind CSS**

-----

## 数据库表

```sql
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  title TEXT,
  dept TEXT,
  role TEXT NOT NULL DEFAULT 'staff', -- ceo/admin/head/staff
  invite_code TEXT UNIQUE NOT NULL,
  color TEXT DEFAULT '#888',
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE phases (
  id TEXT PRIMARY KEY,
  label TEXT NOT NULL,
  date_range TEXT,
  color TEXT,
  sort_order INTEGER DEFAULT 0
);

CREATE TABLE tasks (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  description TEXT,
  phase TEXT REFERENCES phases(id),
  deadline DATE NOT NULL,
  grace_deadline DATE,
  deliverable TEXT,
  reviewer_id TEXT REFERENCES users(id),
  feishu_link TEXT,
  status TEXT DEFAULT 'pending', -- pending/active/review/done
  priority INTEGER DEFAULT 0,   -- 0普通 1重要 2紧急
  parent_id TEXT REFERENCES tasks(id) ON DELETE CASCADE,
  depends_on TEXT,
  sort_order INTEGER DEFAULT 0,
  created_by TEXT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  completed_at TIMESTAMP
);

CREATE TABLE task_assignees (
  task_id TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  user_id TEXT NOT NULL REFERENCES users(id),
  PRIMARY KEY (task_id, user_id)
);

CREATE TABLE task_logs (
  id SERIAL PRIMARY KEY,
  task_id TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  user_id TEXT,
  action TEXT NOT NULL,
  old_value TEXT,
  new_value TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);
```

## 第1轮功能（只做4个）

### 1. 邀请码登录

- 输入邀请码 → 验证 → JWT(7天) → httpOnly cookie → 跳转 /dashboard
- 登出清 cookie
- 格式 `DP-XXXX-XXXX`

### 2. 主看板（/dashboard）

**三个 Tab：**

- **我的任务**（所有人可见）：当前用户负责的任务，按阶段分组
- **全部任务**（CEO/Admin看全部，Head看自己+部门）：按阶段分组，可按状态/人员筛选
- **人员视图**（CEO/Admin可见）：按人分组，每人下面列任务

**任务卡片显示：**

- 标题 + 优先级标签（🔴紧急 🟡重要）
- 负责人色块 + 姓名
- 状态标签（灰pending / 蓝active / 橙review / 绿done）
- 截止日期 + 逾期计算（⚡还剩X天 / 橙色宽限期 / 红色逾期X天）
- 交付物名称

**点击卡片展开详情：**

- 描述、负责人、考核人、截止日期、宽限期、交付物
- 状态切换按钮（pending → active → review → done）
- 飞书链接编辑框
- 操作日志列表

### 3. 任务状态流转

- 点击切换状态，写入 task_logs
- 完成时填充 completed_at
- 被依赖阻塞的任务显示🔒，不可切为 active（depends_on 中的任务未全部 done）

### 4. JSON 粘贴同步页面（/dashboard/sync）⭐

仅 CEO 可访问。页面有一个大文本框，粘贴 JSON 后先预览再确认执行。

**JSON 格式（严格遵守）：**

```json
{
  "sync_date": "2026-02-21",
  "sync_by": "alex",
  "summary": "说明（可选）",

  "updates": [
    {
      "id": "t01",
      "status": "done",
      "note": "已完成，合同盘点表已归档"
    }
  ],

  "new_tasks": [
    {
      "title": "【AI知识库】阶段一验收",
      "description": "描述...",
      "assignees": ["michael"],
      "reviewer_id": "alex",
      "deadline": "2026-02-18",
      "grace_deadline": "2026-02-20",
      "phase": "cny",
      "priority": 1,
      "deliverable": "验收通过/修改清单",
      "status": "pending",
      "depends_on": "t01,t02",
      "subtasks": ["子任务1", "子任务2"]
    }
  ],

  "new_comments": [
    {
      "task_id": "t07",
      "content": "初稿已审阅，需要修改细节"
    }
  ]
}
```

**字段说明：**

updates 每条：id(必填), status, note, priority, deadline, grace_deadline, feishu_link — 都是可选更新

new_tasks 每条：title+assignees+deadline(必填), 其余可选。reviewer_id 默认 “alex”，status 默认 “pending”。自动生成 id 格式 `t-{时间戳}`。subtasks 数组会创建为子任务（parent_id 指向主任务）。

new_comments 每条：task_id+content(必填)，以当前用户身份发表。

**处理流程：**

1. 粘贴 JSON → 点「解析预览」→ 分三个表格展示：更新/新增/评论
1. 不存在的任务ID、缺必填字段的条目标黄跳过，不影响其他
1. 用户点「确认同步」→ 执行写入 → 显示结果：✅更新X条/新增X条/评论X条/⚠️跳过X条
1. 页面底部显示最近10次同步历史

页面上放一个「📋 粘贴示例」按钮，自动填入上面的示例 JSON。
