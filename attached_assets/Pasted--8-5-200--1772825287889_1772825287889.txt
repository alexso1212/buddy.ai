## 二、为什么不能用固定评分

你说得对——每个公司不一样。一家贸易公司的”产品目录”比”代码规范”重要100倍，但在软件公司正好反过来。

**固定评分的问题**：

```
我之前写的：
  "组织架构图" → 5分
  "发票" → 1分

但实际上：
  一家制造企业的"质检标准.pdf" 可能是最核心的知识
  一家律所的"合同模板.docx" 才是最重要的
  一家电商的"产品目录.xlsx" 比员工手册更常被查询
```

## 三、自适应评分方案

### 方案：两维度评分

不用一个维度打分，改为两个维度独立评分：

|维度        |衡量什么                  |影响什么              |
|----------|----------------------|------------------|
|**组织架构价值**|这个文件能帮助我理解公司结构、人员、岗位吗？|决定是否送给 Opus 提取组织信息|
|**知识库价值** |这个文件被员工日常查询的可能性有多大？   |决定在知识库中的优先级和可见性   |

修改 Haiku prompt 返回两个评分：

```json
{
  "category": "policy",
  "orgRelevance": 4,
  "kbRelevance": 5,
  "orgReason": "包含部门职责描述和汇报关系",
  "kbReason": "考勤和请假是员工最常查询的制度",
  "mentionedDepartments": ["销售部", "行政部"],
  "mentionedRoles": ["销售经理"],
  "mentionedNames": ["张三", "Sam"],
  "sensitivity": "low"
}
```

- **orgRelevance ≥ 3** → 送 Opus 分析组织架构
- **kbRelevance ≥ 2** → 存入知识库（几乎所有文件都入库）
- **sensitivity = high** → 自动设 visibility=admin

### 评分标准（给 Haiku 的 prompt）

```
## 评分标准

orgRelevance（对理解组织架构的价值，1-5）：
  5 = 直接包含组织架构信息（组织架构图、花名册、通讯录）
  4 = 包含岗位职责或人员信息（岗位说明书、劳动合同、KPI考核表）
  3 = 间接包含组织信息（员工手册中提到部门、SOP中提到负责人）
  2 = 可能有零星的人名或部门提及（会议纪要、项目方案）
  1 = 与组织架构完全无关（产品目录、财务数据、发票）

kbRelevance（员工日常查询价值，1-5）：
  5 = 员工会经常查询的制度和流程（考勤制度、报销流程、请假规定）
  4 = 工作中需要参考的文档（SOP、产品手册、销售话术）
  3 = 偶尔需要查看的资料（培训记录、项目方案、竞品分析）
  2 = 较少查询但有存档价值（合同、协议、年度计划）
  1 = 几乎不会被员工查询（发票、银行流水、物流单号）

sensitivity（敏感程度）：
  high = 涉及薪资、个人隐私、商业秘密 → 自动设为仅管理层可见
  medium = 涉及合同条款、客户信息 → 建议管理层可见
  low = 可全员公开
```

这样AI的评分不是主观的”这个文件重不重要”，而是两个维度各自有明确的标准。不同行业的文件在两个维度上的分数分布不同，但评分标准本身是通用的。

## 四、分类体系更新

之前的 category 只有 5 种，不够细。扩展为：

```typescript
type DocumentCategory = 
  // 组织与人事
  | 'org_chart'      // 组织架构图
  | 'roster'         // 花名册/通讯录
  | 'jd'             // 岗位说明书
  | 'contract'       // 劳动合同
  | 'kpi'            // 考核标准
  
  // 规章制度
  | 'policy'         // 规章制度（考勤、报销、行政等）
  | 'handbook'       // 员工手册（综合性文档）
  | 'sop'            // 标准操作流程
  
  // 业务
  | 'product'        // 产品相关（目录、手册、规格）
  | 'sales'          // 销售相关（话术、客户、报价）
  | 'project'        // 项目相关（方案、计划、纪要）
  
  // 财务法务
  | 'finance'        // 财务相关
  | 'legal'          // 法务合同/协议
  
  // 品牌与市场
  | 'marketing'      // 市场营销相关
  | 'brand'          // 品牌相关
  
  // 技术
  | 'technical'      // 技术文档
  
  // 其他
  | 'general';       // 无法分类的
```

Haiku prompt 中给出所有分类选项让它选。分类越细，后续在知识库管理页面的筛选就越好用。

## 五、给 Haiku 的完整评分 Prompt

```
你是一个企业文档分析助手。请分析以下企业文件，返回纯 JSON。

只看文件名和文件开头内容（前500字符），快速判断以下信息：

{
  "category": "从以下选项中选一个：org_chart/roster/jd/contract/kpi/policy/handbook/sop/product/sales/project/finance/legal/marketing/brand/technical/general",
  
  "orgRelevance": 1-5（对理解组织架构的价值），
  "kbRelevance": 1-5（员工日常查询的价值），
  
  "orgReason": "一句话说明为什么给这个 orgRelevance 分数",
  "kbReason": "一句话说明为什么给这个 kbRelevance 分数",
  
  "sensitivity": "high/medium/low",
  
  "summary": "一句话概括文件内容（20字以内）",
  "mentionedDepartments": ["识别到的部门名称"],
  "mentionedRoles": ["识别到的岗位/职位名称"],
  "mentionedNames": ["识别到的人名"],
  
  "suggestedVisibility": "org/admin/department",
  "suggestedDepartment": "如果 suggestedVisibility=department，填哪个部门"
}

orgRelevance 评分标准：
5 = 直接包含组织架构信息（组织架构图、花名册、通讯录）
4 = 包含岗位职责或人员信息（岗位说明书、劳动合同、绩效考核表）
3 = 间接包含组织信息（员工手册中提到部门、SOP中提到负责人、项目方案中有分工）
2 = 可能有零星的人名或部门提及（会议纪要、工作报告）
1 = 与组织架构完全无关（产品手册、财务数据、发票、市场资料）

kbRelevance 评分标准：
5 = 员工高频查询（考勤制度、报销流程、请假规定、产品FAQ）
4 = 工作参考文档（SOP、产品手册、销售话术、技术规范）
3 = 偶尔参考（培训计划、项目方案、竞品分析）
2 = 低频但有存档价值（合同、年度计划、品牌手册）
1 = 几乎不会被查询（发票、银行流水、物流单号、水电费通知）

sensitivity 判断：
high = 涉及个人薪资、银行信息、商业核心机密
medium = 涉及合同条款、客户名单、财务概况
low = 可以全员公开的制度、流程、产品信息
```

## 六、筛选逻辑更新

```typescript
// 阶段 0 文件名过滤后
// 阶段 1 Haiku 评分后

// 送 Opus 的条件：orgRelevance >= 3
const orgRelevantFiles = scoredFiles.filter(f => f.orgRelevance >= 3);

// 存入知识库的条件：kbRelevance >= 1（几乎所有文件都入库）
const kbFiles = scoredFiles.filter(f => f.kbRelevance >= 1);
// 但 sensitivity=high 的自动设 visibility=admin

// 自动设可见性
for (const f of kbFiles) {
  if (f.sensitivity === 'high') {
    f.suggestedVisibility = 'admin';
  } else if (f.sensitivity === 'medium') {
    f.suggestedVisibility = 'admin'; // 默认管理层可见，用户可改
  }
}

console.log(`[Setup] ${extractedFiles.length} 个文件 → ${orgRelevantFiles.length} 个送Opus分析 → ${kbFiles.length} 个入知识库`);
```
