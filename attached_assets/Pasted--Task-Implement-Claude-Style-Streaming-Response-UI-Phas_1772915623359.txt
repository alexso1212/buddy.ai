### 2. Markdown Rendering in Streaming Text

Apply markdown formatting in real-time as tokens stream in:

|Markdown            |Rendered As                                                                                            |
|--------------------|-------------------------------------------------------------------------------------------------------|
|`**bold**`          |`<strong>`, font-weight 600                                                                            |
|`*italic*`          |`<em>`, font-style italic                                                                              |
|``inline code``     |`<code>`, font-family monospace, background #2a2a2a, border-radius 4px, padding 2px 6px, font-size 13px|
|`[text](url)`       |`<a>`, color #7ab5e0, no underline, underline on hover                                                 |
|`## Heading`        |font-size 18px, font-weight 600, margin-top 20px, margin-bottom 6px                                    |
|`- item` or `* item`|`<ul><li>`, standard disc marker                                                                       |
|`1. item`           |`<ol><li>`, decimal marker                                                                             |

Use a streaming-compatible markdown parser (e.g. `marked` with streaming mode, or custom incremental parser). The key requirement: partial markdown (e.g. `**bol` before the closing `**`) should NOT flash raw asterisks to the user. Either buffer the incomplete token or render it as plain text until the closing marker arrives.

### 3. Code Blocks

When the model outputs a code fence (`````), render a styled code container:

**Layout**:

```
┌─ typescript ─────────────────────── [Copy] ─┐
│                                              │
│  const x = await fetch(url);                 │
│  const data = await x.json();                │
│                                              │
└──────────────────────────────────────────────┘
```

**Specs**:

- Background: #1e1e1e
- Border: 1px solid #404040
- Border radius: 8px
- Margin: 8px 0 (compact)
- Header: language label left, Copy button right, separated by 1px border-bottom #404040, padding 8px 12px, font-size 12px, color #a0a0a0
- Code area: padding 16px, font-family monospace, font-size 13px, line-height 1.5, color #e8e8e8, overflow-x auto

**Streaming behavior**:

1. When opening ````` detected → render empty container with header immediately
1. Code text streams inside the container token by token
1. Apply syntax highlighting progressively (use highlight.js or Prism, re-highlight every ~200ms for performance)
1. When closing ````` detected → Copy button fades in (300ms)

**Copy button** (hidden during streaming, visible after):

```svg
<svg width="14" height="14" viewBox="0 0 16 16" fill="none" stroke="#a0a0a0" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round">
  <rect x="5" y="5" width="8" height="8" rx="1.5"/>
  <path d="M3 11V3.5A1.5 1.5 0 0 1 4.5 2H11"/>
</svg>
```

- On click: copy code content to clipboard, icon briefly changes to a checkmark for 1.5s then reverts

## DO NOT Implement in This Phase

- Artifact cards with thumbnail
- Side panel / bottom sheet
- Interactive widgets
- Citations
- Background processing banner

## Validation

After implementation, verify:

1. Extended Thinking bar appears with shimmer, text updates, then becomes collapsible
1. Tapping the thinking bar expands/collapses full thinking text
1. Bold, italic, inline code, links, headers, lists all render correctly during streaming
1. No raw markdown symbols flash to the user (buffered properly)
1. Code blocks stream with syntax highlighting, Copy button appears after block closes
1. Tool call cards appear inline with spinner → green check transition
1. All process elements have TIGHT spacing (4px margin), not floating with big gaps
