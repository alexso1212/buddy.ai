## 修复 1：Tasks 路由加 authMiddleware（最紧急）

### 找到这一行

```typescript
app.get("/api/tasks", async (req, res) => {
```

### 改为

```typescript
app.get("/api/tasks", authMiddleware, async (req: any, res) => {
```

### 然后在函数体内，确保查询带 orgId 过滤

找到查询任务列表的逻辑，确保 WHERE 条件包含 `orgId = req.orgId`。

如果当前代码是：

```typescript
const data = await storage.getTasks(/* 某些过滤参数 */);
```

需要确保 `storage.getTasks()` 内部或调用处有 orgId 过滤。检查方式：

```typescript
// 如果 storage.getTasks 不接受 orgId 参数，改为：
const data = await storage.getTasksByOrg(req.orgId);

// 或者如果 getTasks 已有 orgId 参数：
const data = await storage.getTasks({ orgId: req.orgId, ...其他过滤 });

// 如果 storage 里没有按 orgId 过滤的方法，需要加一个
// 或者在路由中手动过滤：
const allTasks = await storage.getTasks(/* 原有参数 */);
const data = allTasks.filter((t: any) => t.orgId === req.orgId);
```

**关键**：最终返回给前端的数据必须只包含 `req.orgId` 对应的任务。

## 修复 4：新增组织修改 API

在 routes.ts 中找到 organizations 相关路由区域，新增：

```typescript
app.patch("/api/organizations/:id", authMiddleware, async (req: any, res) => {
  try {
    const id = parseInt(req.params.id);
    
    // 权限检查：只有 owner 能修改组织信息
    if (req.orgId !== id) {
      return res.status(403).json({ error: '无权修改此组织' });
    }
    
    const userRole = req.userRole || 'member';
    if (userRole !== 'owner') {
      return res.status(403).json({ error: '仅组织所有者可修改组织信息' });
    }
    
    // 允许修改的字段
    const allowedFields = ['name', 'description', 'type', 'tokenBudgetUsd', 'budgetResetDay', 'maxMembers', 'isPublic'];
    const updateData: any = {};
    for (const field of allowedFields) {
      if (req.body[field] !== undefined) {
        updateData[field] = req.body[field];
      }
    }
    
    if (Object.keys(updateData).length === 0) {
      return res.status(400).json({ error: '没有要更新的字段' });
    }
    
    const updated = await storage.updateOrganization(id, updateData);
    if (!updated) {
      return res.status(404).json({ error: '组织不存在' });
    }
    
    await storage.createActivityLog({
      orgId: id,
      userId: req.currentUserId,
      entityType: 'organization',
      entityId: id,
      action: 'update',
      changes: JSON.stringify(updateData),
      source: 'manual',
    });
    
    return res.json({ data: updated });
  } catch (e: any) {
    return res.status(500).json({ error: e.message });
  }
});
```

### 检查 storage.ts 是否有 updateOrganization 方法

如果没有，在 storage.ts 中添加：

```typescript
async updateOrganization(id: number, data: Partial<typeof organizations.$inferInsert>) {
  const [org] = await db.update(organizations)
    .set({ ...data, updatedAt: new Date() })
    .where(eq(organizations.id, id))
    .returning();
  return org || null;
}
```

## 修复 5：任务分配通知（低优先级）

在 `PATCH /api/tasks/:id` 路由中，当 `assigneeId` 发生变化时，创建通知：

找到任务更新路由中的更新逻辑之后，添加：

```typescript
// 在任务更新成功后，检查是否有 assignee 变更
if (req.body.assigneeId && req.body.assigneeId !== existingTask.assigneeId) {
  // 给新负责人发通知
  try {
    await storage.createNotification({
      orgId: req.orgId,
      userId: req.body.assigneeId,
      type: 'task_assigned',
      title: '新任务分配',
      content: `你被分配了任务「${existingTask.title}」`,
      relatedEntityType: 'task',
      relatedEntityId: existingTask.id,
    });
  } catch (notifErr) {
    // 通知失败不影响主流程
    console.error('[Notification] Failed to create assignment notification:', notifErr);
  }
}
```

**注意**：检查 `storage.createNotification` 是否存在，以及 notification 表的字段名是否匹配。参照现有的通知创建代码。
