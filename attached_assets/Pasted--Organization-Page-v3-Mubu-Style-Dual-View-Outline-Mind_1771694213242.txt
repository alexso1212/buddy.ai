# Organization Page v3 — Mubu-Style Dual View (Outline + Mindmap)

> This patch REPLACES all previous org-tree patches. Read this carefully.
> 
> Reference app: **幕布 (Mubu)** — an outline note app where you write content as a nested bullet list, and with ONE BUTTON you switch the same content into a visual mindmap. Both views are fully interactive. Both views work on mobile AND desktop. This is exactly what we want.

-----

## Core Concept: ONE Data, TWO Renderers

Think of it like this:

```
Same data (departments + people + tasks)
        │
        ├──→ Renderer A: Outline List (text-based, vertical, editable)
        │
        └──→ Renderer B: Mindmap Tree (visual, spatial, read + drill-down)
```

The user sees a toggle button at the top. Tapping it switches between the two renderers INSTANTLY. No page reload. No route change. Same URL. The data doesn’t change — only how it’s drawn on screen.

**Both renderers must work on ALL screen sizes: phone, tablet, desktop.**

-----

## The Toggle

At the very top of the /organization page, place this toggle:

```
┌──────────────────────────────────────────────┐
│  📋 大纲          🧠 导图         ⏳ 审批(2)  │
│  ━━━━                                        │
└──────────────────────────────────────────────┘
```

- These are tab-style toggles (underline active tab)
- Tapping “大纲” renders the Outline view
- Tapping “导图” renders the Mindmap view
- Tapping “审批” renders the approval panel (already exists)
- Default view: “导图” (mindmap) on desktop, “大纲” (outline) on mobile
- Switching is instant (no loading spinner, no animation delay >0.2s)
- The toggle looks and behaves identically on mobile and desktop

The phone user can:

- **Pinch to zoom** in/out on this tree
- **Drag** to pan around
- **Tap a node** to expand its detail card
- **Double-tap empty space** to zoom-fit the whole tree

This is critical: **the mobile mindmap is a real mindmap, not a list.** It is a zoomable, pannable canvas with nodes and connecting lines. The user sees the spatial relationships. They zoom in to see details, zoom out to see the big picture.

### Implementation approach for mindmap canvas:

Use **SVG** or **Canvas** for rendering the mindmap. Recommended approach:

```
Option A (recommended): React + SVG
- Each node is an SVG <g> group with <rect> + <text>
- Connection lines are SVG <path> elements with rounded corners
- Use CSS transform for zoom/pan
- Touch events: onTouchStart/Move/End for pinch-zoom and pan
- This works identically on mobile and desktop

Option B: Use a lightweight library
- react-flow (https://reactflow.dev) — supports nodes, edges, zoom, pan out of box
- OR use d3-hierarchy for tree layout calculation + SVG for rendering
```

DO NOT use HTML div-based layout for the mindmap. It won’t support proper zoom/pan on mobile. SVG or Canvas is required.

### Mindmap node design:

**Collapsed node (default):**

```
┌─ completion-color left border (4px) ──────┐
│                                      🔴   │  ← urgency dot (if any)
│  运营总部                                  │
│  安洲 · 7人                               │
│  ██████░░░░ 62%                           │  ← mini progress bar
└───────────────────────────────────────────┘
```

- White card, subtle shadow, 8px border-radius
- Left border 4px colored by completion rate (green/blue/amber/red/gray)
- Very subtle background tint by workload level (see color system below)
- Node size: approximately 160px wide × 70px tall (scales with zoom)

**Planned/empty department:**

- Dashed border, gray text, no progress bar

### Mindmap interactions:

|Action                                          |What happens                                                                    |
|------------------------------------------------|--------------------------------------------------------------------------------|
|Tap node                                        |Expand detail card (overlay panel on right side desktop, bottom sheet on mobile)|
|Long press node                                 |Focus mode — this branch highlighted, everything else dims to 15% opacity       |
|Tap fold button (small ◉ at node edge)          |Collapse/expand children. When collapsed, show badge “3” for child count        |
|Pinch (mobile) or scroll-wheel (desktop)        |Zoom in/out (50% to 200%)                                                       |
|Two-finger drag (mobile) or click-drag (desktop)|Pan the canvas                                                                  |
|Double-tap empty area                           |Zoom to fit entire tree                                                         |

## Semantic Color System

Every color means something. No decorative colors.

### Node border color = Completion Rate

|Rate    |Color|Hex    |
|--------|-----|-------|
|≥ 80%   |Green|#10B981|
|60-79%  |Blue |#3B82F6|
|40-59%  |Amber|#F59E0B|
|< 40%   |Red  |#EF4444|
|No tasks|Gray |#9CA3AF|

### Node background tint = Workload (very subtle)

|Level     |Tasks per person|Tint                  |
|----------|----------------|----------------------|
|Overloaded|≥ 6 per person  |rgba(239,68,68,0.05)  |
|Heavy     |4-5 per person  |rgba(249,115,22,0.05) |
|Normal    |2-3 per person  |transparent           |
|Light     |0-1 per person  |rgba(156,163,175,0.05)|

### Urgency dot (top-right corner of node)

|Condition        |Dot        |
|-----------------|-----------|
|Has overdue tasks|🔴 red      |
|Due within 2 days|🟡 yellow   |
|Has blocked tasks|🔒 lock icon|
|All clear        |No dot     |

### Connecting lines

|Condition                  |Color  |Style |
|---------------------------|-------|------|
|Normal                     |#D1D5DB|Solid |
|Has tasks due within 2 days|#F59E0B|Solid |
|Has overdue tasks          |#EF4444|Solid |
|Planned department         |#D1D5DB|Dashed|

### Color Legend Bar (always visible at bottom)

```
边框: 🟢≥80% 🔵60-79% 🟡40-59% 🔴<40% ⚪无任务 | 标记: 🔴逾期 🟡临期 🔒阻塞 | 线: ━正常 ━临期 ━逾期 ┈待招
```

## Component Architecture

```
components/org/
  OrgPage.tsx               ← page container, holds the view toggle
  OrgViewToggle.tsx         ← "大纲 | 导图 | 审批" tab bar
  
  // Shared (used by both views)
  OrgDetailPanel.tsx        ← side panel / bottom sheet detail card
  OrgPersonPopover.tsx      ← mini profile on tap person
  OrgColorLegend.tsx        ← bottom legend bar
  useOrgData.ts             ← shared data hook (fetch once, feed both views)
  
  // Outline view
  OrgOutline.tsx            ← the outline/list renderer
  OrgOutlineRow.tsx         ← single row (department or person)
  
  // Mindmap view  
  OrgMindmap.tsx            ← SVG canvas with zoom/pan
  OrgMindmapNode.tsx        ← single SVG node card
  OrgMindmapEdge.tsx        ← SVG connector line between nodes
  OrgMindmapControls.tsx    ← zoom buttons + fit button overlay
```

Key architecture rule: **`useOrgData.ts` fetches data ONCE. Both `OrgOutline` and `OrgMindmap` receive the same data as props. Switching views does NOT re-fetch data.**

## Summary for Replit

To be absolutely clear, here is what you need to build:

1. **One page** at /organization
1. **One data source** (departments + users + their task stats)
1. **Two rendering modes** toggled by tabs at the top:
- **大纲 mode**: a nested bullet list with indentation, expand/collapse arrows, and inline stats. Works on mobile and desktop with the same layout (just different sizing).
- **导图 mode**: a visual tree diagram rendered in SVG on a zoomable/pannable canvas. Works on mobile (top-down vertical layout + pinch zoom) and desktop (left-to-right horizontal layout + scroll zoom). This is NOT an HTML div layout. It MUST be SVG or Canvas to support proper zoom/pan touch gestures.
1. **Tapping any department** in EITHER view opens the SAME detail panel (side panel on desktop, bottom sheet on mobile)
1. **Both views** show the same color coding: border = completion rate, background tint = workload, dot = urgency
1. The app called **幕布 (Mubu, mubu.com)** does exactly this for notes — outline list ↔ mindmap with one tap. Use it as your primary UI reference.
