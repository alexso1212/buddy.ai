当用户在聊天中开启”知识库”模式时，系统自动检索知识库相关文档，注入 AI 的 context，让 AI 基于企业文档回答问题。

## STEP 1：修改 `server/services/ai/prompts.ts`

在文件**末尾**（现有的 `SYSTEM_PROMPT` 之后），新增知识库增强 prompt：

```typescript
/**
 * 知识库增强 prompt 模板
 * 
 * 当用户开启知识库模式时，将检索到的文档片段注入到 system prompt 中。
 * 这个 prompt 会追加到 SYSTEM_PROMPT 的末尾。
 */
export function buildKnowledgePrompt(chunks: { content: string; documentTitle: string; category: string }[]): string {
  if (!chunks || chunks.length === 0) return '';

  const chunksText = chunks.map((chunk, i) => 
    `### 文档片段 ${i + 1}（来源：${chunk.documentTitle}）\n${chunk.content}`
  ).join('\n\n');

  return `

## 📚 知识库参考文档

以下是从企业知识库中检索到的相关文档片段。请基于这些文档回答用户问题。

${chunksText}

## 知识库回答规则
- 优先基于以上参考文档回答用户问题
- 如果参考文档中包含相关信息，基于文档内容给出准确回答
- 如果参考文档中没有相关信息，明确告知"知识库中暂无相关信息"，然后用你的通用知识尝试回答
- 回答末尾用 📄 标注来源文档名，格式：📄 来源：文档名1、文档名2
- 不要编造文档中没有的信息
- 回答语气保持专业简洁`;
}
```

**注意**：不要修改现有的 `SYSTEM_PROMPT` 常量，只新增 `buildKnowledgePrompt` 函数。

## STEP 3：修改 `server/services/ai/index.ts` — chatStream()

### 3.1 修改 chatStream 的 context 参数类型

**找到** `chatStream()` 的签名（约第 345 行）：

```typescript
export async function* chatStream(
  message: string,
  conversationHistory: { role: string; content: string | any[] }[],
  context: { currentUserId: number; currentUserName: string; customSystemPrompt?: string; model?: string; extendedThinking?: boolean; orgId?: number },
  attachments?: { type: string; name: string; mimeType: string; base64: string }[]
)
```

**在 context 类型中新增两个字段**，改为：

```typescript
  context: { currentUserId: number; currentUserName: string; customSystemPrompt?: string; model?: string; extendedThinking?: boolean; orgId?: number; knowledgeBaseEnabled?: boolean; userRole?: string; userDeptId?: number | null },
```

### 3.2 在 chatStream 函数体内，system prompt 构建之后插入 KB 检索

**找到**函数体开头的这几行（约第 351-356 行）：

```typescript
  const hasAttachments = !!(attachments && attachments.length > 0);
  const taskCategory = await classifyTask(message, hasAttachments);
  const config = getConfigForTask(taskCategory, context.model, context.extendedThinking);
  const modelName = config.model;
  const { prompt: systemPrompt } = await buildContextualSystemPrompt({ ...context, model: modelName }, 'streaming');
  const aiClient = getClientForModel(modelName);
```

**替换为**（改动标注了 `// ← KB 新增`）：

```typescript
  const hasAttachments = !!(attachments && attachments.length > 0);
  let taskCategory = await classifyTask(message, hasAttachments);
  
  // ← KB 新增：如果开启了知识库模式，覆盖分类
  if (context.knowledgeBaseEnabled) {
    taskCategory = 'knowledge_qa';
  }
  
  const config = getConfigForTask(taskCategory, context.model, context.extendedThinking);
  const modelName = config.model;
  let { prompt: systemPrompt } = await buildContextualSystemPrompt({ ...context, model: modelName }, 'streaming');
  
  // ← KB 新增：知识库检索并注入 prompt
  let kbSources: string[] = [];
  if (context.knowledgeBaseEnabled && context.orgId) {
    try {
      const { searchKnowledge } = await import('./../../services/kb/search');
      const { buildKnowledgePrompt } = await import('./prompts');
      
      const kbResults = await searchKnowledge({
        orgId: context.orgId,
        query: message,
        topK: 5,
        userRole: context.userRole || 'member',
        userDeptId: context.userDeptId || null,
      });
      
      if (kbResults.length > 0) {
        const kbPrompt = buildKnowledgePrompt(kbResults.map(r => ({
          content: r.content,
          documentTitle: r.documentTitle,
          category: r.category,
        })));
        systemPrompt += kbPrompt;
        kbSources = [...new Set(kbResults.map(r => r.documentTitle))];
        console.log(`[KB] Injected ${kbResults.length} chunks from: ${kbSources.join(', ')}`);
      } else {
        console.log(`[KB] No results found for query: ${message.slice(0, 50)}...`);
      }
    } catch (err: any) {
      console.error(`[KB] Search error (non-fatal):`, err.message);
      // KB 检索失败不影响正常对话
    }
  }
  
  const aiClient = getClientForModel(modelName);
```

**关键点**：

- `let` 替代 `const` 用于 `taskCategory` 和 `systemPrompt`（因为 KB 模式需要修改它们）
- KB 检索用 dynamic import（`await import`），这样即使 KB 模块有问题也不影响 AI 核心加载
- 整个 KB 逻辑包在 try-catch 中，失败不影响正常对话
- `import` 路径是 `./../../services/kb/search`（从 `server/services/ai/index.ts` 到 `server/services/kb/search.ts`）

### 3.3 确认 import 路径

从 `server/services/ai/index.ts` 到 `server/services/kb/search.ts` 的相对路径：

```
server/services/ai/index.ts  →  ../kb/search
```

所以 import 应该是：

```typescript
const { searchKnowledge } = await import('../kb/search');
```

同理，prompts.ts 的 import：

```typescript
const { buildKnowledgePrompt } = await import('./prompts');
```

**让 Replit Agent 根据实际目录结构确定正确的 import 路径。**

## STEP 5：处理 codeToolChatStream 路径

在 `/api/ai/chat/stream` 路由中，可能有两个 generator 分支：

- `codeToolChatStream`（Anthropic native SDK，代码上下文模式）
- `aiChatStream`（OpenAI compatible，普通聊天模式）

**知识库模式只需要注入到 `aiChatStream` 路径**。`codeToolChatStream` 是代码分析模式，不需要知识库。

所以：如果用户同时开启了 codeContext 和 knowledgeBase（极端情况），`codeContext` 优先，忽略 `knowledgeBase`。在路由中的分支逻辑应该是：

```typescript
if (codeContextEnabled) {
  // 走 codeToolChatStream，不注入 KB
  generator = codeToolChatStream(...);
} else {
  // 走 aiChatStream，KB 注入已在 chatStream 函数内部处理
  generator = aiChatStream(message, history, {
    ...context,
    knowledgeBaseEnabled,
    userRole: req.userRole || 'member',
    userDeptId: req.userDeptId || null,
  }, attachments);
}
```

## STEP 6：确认 userRole 和 userDeptId 在 req 上可用

在 routes.ts 中的 `/api/ai/chat/stream` 路由里，需要获取当前用户的 role 和 deptId。

检查 `authMiddleware` 是否在 `req` 上设置了这些字段：

- `req.userRole` — 如果没有，从数据库查：`const user = await storage.getUserById(req.currentUserId); const userRole = user?.role || 'member';`
- `req.userDeptId` — 如果没有，同理：`const userDeptId = user?.deptId || null;`

**最安全的方式**：在路由处理函数的开头直接查用户信息：

```typescript
// 在路由处理函数内部
const currentUser = await storage.getUserById(req.currentUserId);
const userRole = currentUser?.role || 'member';
const userDeptId = currentUser?.deptId || null;
```
